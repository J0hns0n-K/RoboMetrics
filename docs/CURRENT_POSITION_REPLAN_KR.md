# 지도 변경 후 현재 위치에서 다시 찾기

2026-10-29. 상태를 저장해 이어가는 참고 구현은 처음 지도 복사본에만 유효하다. 새 벽이 생긴 상황은 별도로 확인해야 한다. 이번 과제는 자동 감지나 동적 탐색 알고리즘을 구현하는 것이 아니라, 명시적으로 바뀐 지도에서 예전 남은 경로를 검사하고 현재 위치부터 새로 탐색하는 작은 시뮬레이션 검증이다.

## 실행 전 질문과 예측

AI가 만든 지도에서 학생은 현재 R에서 목표 G까지의 최소 이동 횟수를 **4번**이라고 예상했다. [준비된 입력](../experiments/changed-map-current-position-detour-01.scenario.json)에 실행 전에 원문을 기록했다. 학생은 이동 순서·검토량을 따로 제시하지 않았고 지도·방법·코드는 AI 지원이다. [이전 초안](../experiments/changed-map-remaining-route.design.json)은 당시 예측 미제출 상태 그대로 보존한다.

```text
S · R # G
· · · · ·
```

S는 원래 출발 (0,0), R은 현재 (2,0), G는 (4,0)이다. 새 벽은 (3,0)이며 나머지 칸은 그대로다. 네 방향·단위 비용이고 대각선 이동은 없다. 파서용 지도에서는 **현재 R을 새 S로 표시**하고 원래 출발 칸은 빈칸으로 둔다. 새 이동 횟수는 R부터 세며 이미 이동한 구간을 섞지 않는다.

## 검증 방법과 범위

1. 벽이 없던 지도에서 전체 옛 경로와 R 이후의 남은 경로가 유효한지 확인한다.
2. 새 벽이 있는 지도에서 같은 남은 경로가 유효한지 검사한다. 이 검사 결과는 탐색의 예산 초과·도착 불가와 별도로 기록한다.
3. 현재 R에서 A* FIFO, 예산 30으로 한 번 새로 탐색한다. 성공 경로를 새 지도에서 검증한다.
4. 공유 탐색 함수를 호출하지 않는 별도 BFS로 현재 위치부터의 최단 거리를 확인하고 학생의 길이 예측과 대조한다.

[도구](../scripts/check-current-position-detour.mjs)는 입력·소스가 커밋되어야 실행하고 기존 출력 파일이 있으면 탐색 전에 거부한다. 원시 파일에 전체 입력, 옛 경로 검사, 새 경로, 검토량, 독립 거리 확인, 예측 대조, 실행 주체와 Git 소스 해시를 보존한다.

새 BFS의 수작업으로 확인 가능한 도달·도착 불가·이미 목표인 경우와 원점이 아닌 시작점 검사를 포함해 [전체 37개 테스트](../data/map-updates/current-position-detour-tests-01.tap)가 통과했다. 이는 AI가 작성·실행한 회귀 검사다. 기존 35개 테스트·원시 결과는 덮어쓰지 않는다.

## 커밋 후 실행 결과

예측·입력·소스 커밋 `922b3b96b6da020f4a55e754651860da82d66cac` 뒤 AI가 실행했다. [원시 산출물](../data/map-updates/current-position-detour-run-01.json)과 [검증 기록](../data/map-updates/current-position-detour-validation-01.json)은 지도 1건의 다음 결과를 보존한다.

| 검사 | 결과 |
|---|---|
| 벽이 없던 지도에서 옛 남은 경로 | 유효 |
| 벽 추가 후 같은 남은 경로 | 무효 — (3,0)이 막힘 |
| 바뀐 지도에서 현재 R부터 새 A* FIFO, 예산 30 | 성공, 4번 이동, 6칸 검토 |
| 별도 BFS의 최소 남은 이동 횟수 | 4 |
| 학생의 실행 전 예상 4번 | 이번 지도에서 일치 |

AI가 찾은 경로는 `(2,0) → (2,1) → (3,1) → (4,1) → (4,0)`이다. 즉 아래 1번, 오른쪽 2번, 위 1번이며 이미 지나온 구간을 더하지 않는다. 새 벽 때문에 아래 줄을 거쳐 다시 위로 가야 하므로 수직 이동이 최소 2번, R과 G 사이 수평 이동이 최소 2번 필요하다. 이 경로는 그 합 4를 달성하며 별도 BFS와도 일치한다. 학생은 길이만 예상했고 이 이동 순서·증명·검토량은 AI 확인이다.

`OLD_REMAINING_PATH_INVALID`는 **예전 경로를 그대로 사용할 수 없다는 검사 상태**다. 목표 도착 불가나 예산 초과가 아니다. 이번에는 실제로 다른 유효 경로가 남아 있었다. 실행은 공유 탐색기 1회와 별도 BFS 1회이며 코어·파서는 이전 검증과 동일하다. 소스·TAP 해시, 입력된 한 칸 변경, 현재 시작점, 경로, 덮어쓰기 거부와 원시 바이트 보존을 확인했다. 설정 실행 뒤 전체 테스트를 반복한 것으로 표시하지 않는다.

다음은 학생이 [두 번째 벽 초안](../experiments/changed-map-second-wall.design.json)의 아래 줄 빈칸 하나를 골라 R에서 G로 못 가게 만드는 지도 설계 과제다. 선택은 아직 없고 실제로 도착 불가가 되는지는 후속 확인 대상이다.

지도 변경은 외부에서 명시적으로 제공한다. 저장 세션의 점진적 갱신, 센서 입력, 주행 제어, 충돌 측정이나 실제 로봇 성능은 구현·검증 범위에 포함하지 않는다.
