# 목표 방향의 막다른 길 — 4칸 선택, 실행 전 예상 대기

무작위 지도 두 묶음에서 나타난 결과가 다른 구조에서도 유지되는지 살펴본다. 학생은 두 가지 AI 제안 중 **1번**을 선택했고, 2026-10-29에 통로 길이 질문에 **4**라고 답했다. 따라서 4칸 후보를 선택한 지도로 확정했다. 실행 전 예상과 결과는 아직 없다.

## AI가 제안한 기본 틀

S는 출발, G는 목표, #은 벽, .은 빈칸이다. 가로 7칸·세로 3칸이며 상하좌우로만 움직인다. 아래쪽 통로를 포함한 기본 틀은 AI 제안이다.

막다른 통로가 S 오른쪽으로 4칸인 후보:

```text
S....#G
.#####.
.......
```

막다른 통로를 2칸으로 줄인 후보:

```text
S..###G
.#####.
.......
```

길이는 S를 제외하고 오른쪽으로 이어지는 빈칸 수다. 두 후보는 첫째 줄의 두 칸만 다르고, 크기·출발점·목표·나머지 벽은 같다.

## 선택 기록과 다음 항목

학생 원문 **4**를 통로 길이 4칸의 선택으로 기록했다. 이는 AI 틀 안의 안내된 설계 선택이며, 전체 지도를 독립적으로 설계하거나 코드를 작성한 것으로 기록하지 않는다. 다음에는 이 지도에서 ①과 ② 중 어느 규칙의 검토 칸 수가 적을지, 비슷할지, 아직 모르겠는지 실행 전에 남긴다. 기존 무작위 지도에 대한 예상을 새 지도에 자동으로 적용하지 않는다.

선택은 [설계 JSON](../experiments/goal-side-dead-end.design.json)에, 확정한 지도와 비교 조건은 [시나리오 초안](../experiments/goal-side-dead-end-04.scenario.json)에 기록했다. 초안은 예상이 비어 있고 실행 가능 상태로 표시하지 않았다. 준비 중에는 탐색 알고리즘을 호출하지 않았다. 같은 지도에서 두 A* 동점 규칙을 명시적으로 적용하고 경로 길이·검토 칸 수를 비교한다. 예산은 결과를 보기 전에 300으로 정했다. 전체 21칸보다 넉넉한 제한으로 검토 순서에 따른 차이를 살펴본다. 기존 고정 지도 실행기는 FIFO만 비교하므로, 두 규칙 비교에는 옵션을 각각 지정하는 평가가 필요하다. 한 지도 결과를 보편적인 우열로 확대하지 않는다.
