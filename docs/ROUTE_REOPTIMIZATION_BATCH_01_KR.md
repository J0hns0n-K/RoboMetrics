# 벽 하나 제거 후 유지·재탐색의 30장 비교

2026-10-29. 학생은 실행 전 예상 질문에 **모르겠어**라고 답했다. 이는 명시적 불확실성이며 모든 지도·일부 지도라는 방향 예측으로 바꾸지 않는다. [준비 프로토콜](../experiments/route-reoptimization-batch-01.protocol.json)에 원문을 기록했다. 학생의 앞선 기본값 선택은 재탐색이지만 이번 표집·벽 선택·비교 방법·코드·실행·최초 분석은 AI 지원이다.

## 고정한 조건

- 16×12, 벽 생성 확률 .19, 기준 시드 20264027. 후보 시드 +1부터 순서대로 검사하고 시작에서 목표로 연결되며 벽이 있는 지도 30장을 채운다. 별도 BFS로 연결성을 확인하고 탈락 후보와 이유도 보존한다. 최대 후보 4,500개다.
- 각 지도에서 벽을 행 우선 순서로 정렬하고 `후보 시드 % 벽 수` 위치의 벽 하나만 없앤다. 균등한 무작위 벽 표집이라고 부르지 않는다. 시작·목표·다른 칸·네 방향 단위 비용은 유지한다. 현재 위치는 이 배치에서 원래 시작점이며 이동 중인 로봇은 아니다.
- 원래 지도에서 무제한 A* FIFO로 기존 최단 경로를 오프라인 확보하고 별도 BFS 거리와 경로를 대조한다. 이 취득 계산은 온라인 정책 비용과 분리한다. 벽 제거 후 기존 경로는 계속 유효해야 한다.
- 같은 기존 경로와 바뀐 지도에서 명시적 유지·재탐색을 각각 평가한다. 정책 호출별 예산은 300, 동점 규칙은 FIFO다. 재탐색이 예산 초과이면 기존 유효 경로를 보존하면서 실패 기록을 남긴다.
- 바뀐 지도의 별도 BFS로 이론적으로 짧아질 수 있는 지도 수를 센다. 예산 안에서 실제 반환 경로가 짧아진 수·놓친 개선·같은 길이·사용 가능한 경로·재탐색 완료·예산 초과·새 검토량을 따로 보고한다. 길이 평균의 분모는 같은 30쌍이다.

이는 30개 부모·수정 쌍을 두 정책에서 재사용하는 비교이며 독립 지도 60장이 아니다. 다른 시드 범위라는 이유만으로 과거 연구와의 통계적 독립성을 주장하지 않는다. 원시 데이터에는 전후 지도·벽 좌표·기존 경로·두 정책의 전체 결과·BFS 거리·후보 감사를 보존한다.

## 구현과 사전 검사

[실행 도구](../scripts/run-route-reoptimization-batch.mjs)는 소스·프로토콜 커밋을 요구하고 기존 출력은 계산 전에 거부한다. 정해진 수를 채우지 못하면 완성된 코호트인 것처럼 결과를 게시하지 않는다.

새 방법 검사 3개를 포함해 [전체 50개 테스트](../data/route-update-policy/reoptimization-batch-tests-01.tap)가 통과했다. 한 벽만 제거·부모 유지, 연결 불가/벽 없음의 후보 분리, 이론적 개선과 예산 제한 후 실제 개선의 분모·상태 구분을 검사했다. 단위 검사는 작은 알려진 제어 지도이며 등록한 30장 코호트를 미리 실행한 것이 아니다.

기존 무작위 연구·유지 정책·재최적화 제어 결과는 덮어쓰지 않는다. 실행 시간·에너지·센서·물리적 로봇 결과도 아니다.

## 고정 프로토콜 실행 결과

프로토콜·학생 불확실성·소스 커밋 `6cc390ac329808b6707e97292dc1db247cd11afd` 뒤 AI가 실행했다. [원시 배치](../data/route-update-policy/reoptimization-batch-run-01.json)와 [검증 기록](../data/route-update-policy/reoptimization-batch-validation-01.json)은 후보 36개 중 연결 불가 6개를 제외한 30쌍을 보존한다. 이후 코호트나 없앤 벽을 바꿔 개선 사례를 찾지 않았다.

| 지표 — 같은 수정 지도 30장, A* FIFO, 예산 300/호출 | 유지 | 재탐색 |
|---|---:|---:|
| 사용 가능 경로 | 30/30 | 30/30 |
| 평균 반환 이동 횟수 — 분모 30 | 26.13 | 26.13 |
| 실제 이동 횟수가 줄어든 지도 | 0/30 | 0/30 |
| 새 탐색기 검토량 합계 | 0 | 3,733 |
| 지도당 평균 새 검토량 | 0 | 124.43 |
| 재최적화 완료 | 실행 안 함 | 30/30 |
| 재최적화 예산 초과 | 실행 안 함 | 0/30 |

바뀐 지도 BFS도 **이론적으로 짧아진 지도가 0/30**임을 확인했다. 재탐색이 이득을 놓친 예산 실패는 아니며, 이번에 선택한 벽 제거로 최단 거리 자체가 변하지 않았다. 이 조건에서는 정책이 추가 검토량을 썼지만 이동 길이 이득은 없었다. 무조건 재탐색이 나쁘다거나 모든 벽 제거가 무의미하다는 결론은 아니다.

## 사후 해석과 계산량 구분

원래 경로 28장은 26번, 2장은 28번이었다. 끝점 (0,0)→(15,11)의 맨해튼 하한은 15+11=26이다. 이미 26번이던 28장은 같은 끝점·네 방향 단위 비용에서 더 짧아질 여지가 없었다. 나머지 두 지도는 시드 20264032와 20264061이며 선택된 벽 (13,5), (15,4)를 제거한 뒤에도 각각 28번이었다. 이는 AI의 사후 수치·구조 분석이며 학생의 사전 가설이나 독립적 발견으로 귀속하지 않는다.

원래 경로를 확보한 오프라인 A*는 30회·검토량 3,650이다. 이후 정책 평가는 60건이지만 새 A* 호출은 재탐색의 30회·검토량 3,733이다. 후보 BFS 36회와 수정 지도 BFS 30회는 별도 검사다. 유지의 새 검토량 0은 지도 복사·경로 유효성 검사 비용까지 0이라는 뜻이 아니다. 시간·에너지로 환산하지 않는다.

AI 검증은 후보 전체와 수락 시드, 생성 지도, 한 칸 편집 규칙, 모든 기존·반환 경로, 요약 분모·합계, 테스트·소스 해시와 출력 보존을 확인했다. 별도 검증 BFS 66회를 추가했지만 공유 탐색기는 다시 실행하지 않았다. 이 계산은 정책의 노드 검토량과 섞지 않는다. 전체 테스트도 배치 뒤 재실행하지 않았다.

최초 대화 질문은 ‘모두/일부’만 제시해 0장을 빠뜨렸다. 등록된 수치 집계는 0을 허용했고 실제 0 결과를 그대로 보존한다. 학생의 답은 명시적 불확실성으로 유지한다.

다음 AI 제안은 [하한 도달 시 생략 규칙 초안](../experiments/manhattan-bound-skip.design.json)이다. 최신 지도에서 남은 길이 유효하고 그 길이가 현재 위치·목표의 맨해튼 하한과 같을 때만 새 최적화를 생략한다. 학생은 이후 **1**을 선택했고 AI가 구현·재비교했다. [후속 결과](MANHATTAN_BOUND_SKIP_KR.md)는 같은 30장에서 경로를 유지하고 검토량 3,733→201을 확인한다. 이는 새 코호트 검증이 아니라 규칙을 제안한 개발 코호트의 재비교이며 최초 무단축 결과를 대체하지 않는다.
