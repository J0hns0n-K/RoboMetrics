# 유효한 경로도 다시 탐색하는 기본 정책

2026-10-29. 기존 경로가 유효하지만 더 짧은 길이 생겼을 때 유지·재탐색 중 학생은 **2**를 선택했다. [선택 원문](../data/learning/valid-route-optimization-choice-01.json)은 목적과 기본값 선택만 기록하며 이유·수치 예측·코드 저작으로 확대하지 않는다. [이전 선택 초안](../experiments/valid-route-optimization-choice.design.json)은 당시 미제출 상태로 보존한다. 초기 [keep-valid 정책](ROUTE_UPDATE_POLICY_KR.md)과 결과도 유지한다.

## 현재 동작

[함수](../src/route-update-policy.mjs) `resolveRouteUpdate`의 기본 `optimization`은 `reoptimize`다. 최신 지도와 현재 위치를 외부에서 전달받은 호출마다 예산 안에서 새 A*를 한 번 실행한다. 자동으로 환경 변경을 감지하거나 주기적으로 실행하는 기능은 없다. 이미 목표에 도달한 경우에는 새 탐색이 필요 없다. `optimization: 'keep-valid'`를 명시하면 이전 유지 방식을 비교할 수 있다.

| 상황 | 경로 처리 | 세부 결과 |
|---|---|---|
| 유효한 옛 길보다 짧은 경로 발견 | 새 경로 사용 | SHORTER_ROUTE_FOUND |
| 유효한 옛 길과 같은 최단 길이 확인 | 옛 경로 유지 | OPTIMALITY_CONFIRMED |
| 유효한 옛 길이 있으나 새 탐색 예산 소진 | 검증된 옛 길 보존 | OPTIMIZATION_BUDGET_EXCEEDED |
| 옛 길이 무효 | 새 경로·도착 불가·예산 초과 구분 | 기존 실패 이유 유지 |

유효 경로 보존의 예산 예외 처리는 **AI가 제안·구현**했다. 학생이 따로 선택한 규칙이 아니다. 이때 최상위 `status`는 KEEP_ROUTE지만 `optimizationStatus`와 `planningResult.reason`은 BUDGET_EXCEEDED다. 실패한 원시 탐색의 빈 경로·null 길이는 그대로 보존하고, 반환하는 사용 가능 경로는 별도의 검증된 옛 경로다. 더 짧은 길을 찾았다고 하거나 목표에 갈 수 없다고 표시하지 않는다. 추가 예산이나 재시도를 자동으로 실행하지 않는다.

현재 모델은 네 방향 단위 비용·알려진 정적 지도·비어 있는 시작과 목표다. A* 성공 시 반환 최단 길이를 옛 유효 길이와 대조한다. 두 동점 규칙을 지원하지만 아래 통제 비교는 FIFO로 고정한다. 센서·로봇 주행·점진적 탐색 상태 복구·브라우저 연동은 포함하지 않는다.

## 확인 방법

[전체 47개 테스트](../data/route-update-policy/reoptimization-tests-01.tap)가 통과했다. 새 확인에는 4번 경로를 2번으로 줄이는 기본 동작, 이미 최단인 경로 확인, 예산 소진 시 유효 경로와 실패 기록의 분리, 현재 위치·동점 규칙 유지가 포함된다. API·기본값 적용·예외 처리·테스트·실행은 AI 지원이다.

[준비 설정](../experiments/route-reoptimization-controls.config.json)은 알려진 3×2 제어 지도에서 벽 제거·변경 없음, 명시적 유지·새 기본값, 예산 30·부족한 예산 1을 비교한다. 같은 네 번 이동하는 이전 경로를 주고, 최신 지도에서 경로 유효성과 별도 BFS 최단 거리를 확인한다. 학생의 새 결과 예측은 없다. 입력·소스를 커밋한 뒤 새 원시 파일로 실행 결과를 보존한다.

## 커밋 후 비교 결과

입력·학생 선택·소스 커밋 `1c48e39b3e8b89b32523ce3a931bcb8df7bb8d08` 뒤 AI가 실행했다. [비교 원시 결과](../data/route-update-policy/reoptimization-comparison-run-01.json)와 [통합 검증](../data/route-update-policy/reoptimization-validation-01.json)은 다음을 연결한다. A* FIFO이며 원래 유효한 경로는 모두 4번 이동이다.

| 최신 지도·방식 | 예산 | 사용 가능 경로의 이동 횟수 | 새 검토량 | 재탐색 결과 |
|---|---:|---:|---:|---|
| 벽 제거·명시적 유지 | 30 | 4 | 0 | 실행 안 함 |
| 벽 제거·새 기본 재탐색 | 30 | 2 | 3 | 더 짧은 최단 경로 |
| 변경 없음·명시적 유지 | 30 | 4 | 0 | 실행 안 함 |
| 변경 없음·새 기본 재탐색 | 30 | 4 | 5 | 같은 최단 길이 확인 |
| 벽 제거·새 기본 재탐색 | 1 | 4 — 기존 길 보존 | 1 | BUDGET_EXCEEDED |

별도 BFS가 벽 제거 지도의 최소 2번과 변경 없는 지도의 최소 4번을 확인했다. 비교는 지도 상태 2개·정책 조건 5건이며 새 A* 3회·검토량 9·별도 BFS 2회다. 학생이 이 수치나 실패 처리 방식을 예측한 것으로 기록하지 않는다. 짧은 길을 찾으려는 선택은 이번 유리한 조건에서 효과가 있었지만, 길이가 그대로인 조건과 예산이 부족한 조건도 보존했다.

[이전 정책 호환 실행](../data/route-update-policy/keep-valid-compatibility-run-01.json)은 옛 설정에 명시적 유지 규칙을 적용한 별도 재실행이다. 알려진 7건의 원래 결과 필드·경로·새 호출 5회·검토량 26이 과거와 일치했다. 새 메타데이터가 추가됐으므로 전체 원시 JSON이 바이트 단위로 같다고 주장하지 않는다. 이전 결과를 덮어쓰지 않았다. 두 도구의 기존 출력 거부·원시 바이트 보존과 테스트·소스 해시도 검증했다. 전체 테스트는 설정 실행 뒤 반복하지 않았다.

다음은 [30장 벽 제거 비교 초안](../experiments/route-reoptimization-batch.design.json)이다. 기존의 유효한 최단 경로를 입력으로 유지·재탐색을 비교하되, 이론적으로 짧아질 수 있는 지도 수와 예산 안에서 실제로 줄인 수를 구분한다. 학생은 **모르겠어**라고 답했고 준비 프로토콜 커밋 뒤 AI가 실행했다. [30장 결과](ROUTE_REOPTIMIZATION_BATCH_01_KR.md)는 실제·이론적 단축 모두 0/30, 양쪽 평균 이동 26.13, 재탐색 추가 검토량 3,733을 보존한다. 모든 재탐색이 완료됐으며 예산 초과 때문이 아니었다. 이미 28장이 하한 26번을 달성했다는 AI 사후 해석이 후속 생략 규칙 제안으로 이어지며 아직 구현하지 않았다.

옛 통합 설정을 다시 실행할 때에는 `keep-valid`를 명시적으로 사용하도록 도구를 수정했다. 이전 원시 결과나 검증 기록을 새 기본값 결과로 바꾸지 않는다. 경로 길이와 새 검토량은 따로 비교하며 시간·에너지 절약이나 모든 지도에서의 개선을 주장하지 않는다.
