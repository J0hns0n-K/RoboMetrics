# 첫 Engineering Task — 이동 거리와 계산량 구분하기

2026-10-27. 이 안내와 실행 도구는 AI가 작성했다. 학생의 지도·예측·해석은 실제 답변이나 파일이 생긴 뒤 별도로 기록한다.

## 1. 지금 완료한 수동 검산

```text
S . .
. . .
. . G
```

한 번에 상하좌우 한 칸씩 이동한다. Junmo는 채팅에서 최소 이동 횟수를 **4**라고 답했다. 오른쪽 두 번, 아래쪽 두 번인 경로로 확인할 수 있다. 이것은 학생이 수행한 작은 수동 검산이다. 알고리즘 구현이나 독립 연구의 완성을 뜻하지 않는다.

## 2. 컴퓨터와 비교

```sh
node --test
node scripts/run-scenario.mjs experiments/reference-open-grid.json data/reference/open-grid-run-02.json
```

두 번째 명령은 AI 참고 실험을 실행한다. 이미 있는 결과는 덮어쓰지 않으므로 새 파일 이름을 쓴다. `pathLength`는 이동 횟수, `expanded`는 컴퓨터가 꺼내 검토한 칸 수다. 이 구현은 출발점과 도착점도 검토한 칸에 포함한다.

본인 말로 기록할 내용:

- 이동 횟수와 검토한 칸 수는 어떻게 다른가?
- 같은 길이를 찾았는데 왜 검토한 칸 수는 다를 수 있을까?
- 빈 지도 한 장으로 어느 알고리즘이 항상 좋다고 결론 낼 수 있을까?

모르면 추측을 사실처럼 쓰지 않는다. 설명을 함께 살펴본 뒤, 무엇을 이해했는지 적는다.

## 3. 학생의 첫 지도 설계 — 다음 수행 단계

1. `experiments/task-01.template.json`을 `experiments/task-01.student.json`으로 복사한다.
2. `rows`에서 `.` 일부를 `#`로 바꿔 장애물을 직접 배치한다. `S`와 `G`는 하나씩 유지한다. 행 길이는 모두 같아야 한다.
3. 실행 **전** 예상 최소 이동 횟수와 이유를 `prediction`에 적는다. 알고리즘 비교 예측은 이해한 범위만 적어도 된다.
4. `contributor`에 이름, `assistance`에 실제 도움을 적고 `status`를 `ready`로 바꾼다. 코드·지도·예측 중 무엇을 직접 했는지 구분한다.
5. 지도와 예측을 별도 커밋한다. AI가 대신 작성하거나 커밋하면 그 사실도 메시지와 Contribution Log에 기록한다. 작성자 이름만으로 독립 기여를 판단하지 않는다.
6. 실행한다:

```sh
node scripts/run-scenario.mjs experiments/task-01.student.json data/student/task-01-run-01.json
```

7. 예상과 실제를 비교한다. 막힌 지도나 두 알고리즘 결과가 같은 지도도 삭제하지 않고 실패·동일 결과로 기록한다.

JSON 편집이 아직 어렵다면 채팅에 같은 폭의 문자 지도를 보내도 된다. 도우미가 옮겨 적은 뒤 원문·학생 설계·AI 입력 지원을 각각 기록한다.

## 4. 이후 확장 과제

기초를 이해한 뒤 **Greedy가 더 긴 경로를 택하는 지도**를 찾아본다. 먼저 충분한 예산으로 경로를 비교하고, 이후 정해진 예산에서 성공 여부를 비교한다. “긴 경로”와 “예산 초과 실패”는 다른 현상이다. 고정 지도 한 장의 반례와 무작위 지도 30장의 통계도 다른 증거다.

완료 조건은 학생 지도·실행 전 예측·커밋·원시 JSON·실제 결과에 대한 본인 설명이다. 현재 안내받은 지도 선택(가운데 장애물)과 실행 전 예측(4번), 입력 커밋, AI가 실행한 원시 결과가 있다. 본인의 해석, 학생 코드와 독립 실험은 아직 미완료다. 정확한 수행 범위는 `TASK_01_DECISION.md`와 Contribution Log를 따른다.
