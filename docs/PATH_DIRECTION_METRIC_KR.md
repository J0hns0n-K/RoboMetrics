# 경로 길이와 방향 전환 횟수

이 지표는 반환된 축 방향 경로의 모양을 설명한다. 길찾기의 우선순위나 경로 선택 기준을 바꾸지 않으며, 운동학·주행 제어·실제 회전 시간이나 에너지 모델은 아니다.

학생은 AI가 제시한 설명용 이동 순서 `→→→↓↓↓`와 `→↓→↓→↓`에 대해 **A: 1번 / B: 5번**이라고 답했다. [원문과 안내 범위](../data/learning/path-turn-count-answer-01.json)를 보존한다. 두 순서 모두 오른쪽3칸·아래3칸이지만 방향 전환 횟수가 다르다. 학생 기여는 이 손계산 답이며 함수·검사·CLI 연결·실행·검증은 AI 지원이다.

## 정의와 구현

[countDirectionChanges](../src/path-metrics.mjs)는 연속한 두 이동의 방향이 달라질 때마다1회를 센다. 처음 바라보는 방향에 맞추는 동작은 제외한다. 같은 직선 구간을 반 칸씩 나누어도 횟수는 늘지 않는다. 되돌아가는 경우도 방향 변경 사건1회이며, 90도 회전 횟수나 회전 각도 합계와는 다르다.

유한한2차원 좌표의 비어 있지 않은 경로를 받는다. 제자리 점 하나는0회다. 빈 경로·중복 점·대각 이동·유효하지 않은 수치는 거부한다. CLI는 `ROUTE_FOUND`인 반환 경로만 측정하고, 실패 시에는 측정할 경로가 없으므로 `null`을 표시한다.

## 이번 확인 범위

[실행 전 프로토콜](../experiments/path-direction-metric-01.protocol.json), [결과·반환 경로·검증](../data/learning/path-direction-metric-run-01.json), [새 지표 검사 TAP](../data/learning/path-direction-tests-01.tap)는 소스 `2f4f3cc2999d9795323f7dc471a42b00bd64c62b`에 연결된다. 기존 지도10번·출발점(1,3)·몸체 반지름0.4/여유0.15·always-fine·FIFO·예산200을 유지했다.

| 도착점 | 결과 | 세계 길이 | 검토 위치 | 방향 전환 |
|---|---|---:|---:|---:|
| (6,1) | ROUTE_FOUND | 8 | 31 | 6 |
| (8,4) | INVALID_ENDPOINT_CLEARANCE | null | 0 | null |

성공 사례는 저장된 CLI 입력을 사용했다. 실패 사례는 메모리에서만 도착점과 파일 URL 해석을 바꾸고 같은 CLI를 실행했다. 실제 파일의 도착점을 자동으로 옮기지 않았다. 두 사례는 같은 알려진 지도의 입력 변형이며 새 독립 지도2장이 아니다. 기존 상태·길이·검토 수와 안내문 동작이 유지됐다.

새 지표 검사5개가 통과했다. 실제 반환 경로도 저장하고, Python으로 이동 벡터를 다시 분류해 방향 전환 수와 세계 길이를 확인했다. 기존 연습 결과에는 전체 경로가 없었으므로 과거 전체 경로와의 동일성 검사를 했다고 주장하지 않는다. 코어·몸체 소스와 연구 원시 자료 해시는 유지됐으며 이전101개 전체 검사를 재실행하지 않았다. 구성된 CLI 실행2회 중 실제 탐색 호출은1회/31검토이고, 추가 BFS나 새 코호트 생성은 없다.

학생은 이어 `↓→→→↓↓`를 직접 제시했다. [입력 보존 후 확인](../data/learning/path-turn-design-validation-01.json)은 총6칸·오른쪽3칸·아래3칸·도착(3,3)·방향 전환2회를 검증한다. 새 경로탐색이나 검사를 반복하지 않았으며 현재 장애물 지도에서의 주행 가능성을 확인한 것은 아니다. 다음은 [이동과 방향 전환에 임의 점수를 부여한 두 경로 비교](../experiments/path-turn-cost-01.design.json)다. 방향 전환 수가 적으면 실제 로봇이 반드시 더 빠르다는 결론은 아직 낼 수 없다.
