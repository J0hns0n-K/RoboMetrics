# Starter 알고리즘 검토

AI가 원본 `src/core.mjs`를 읽고 작성한 분석이다. 학생의 설명이나 구현으로 취급하지 않는다.

## 길을 찾을 때의 두 숫자

- `g`: 출발점에서 지금 살펴보는 칸까지 찾아낸 이동 거리.
- `h`: 장애물이 없다고 가정했을 때, 그 칸에서 도착점까지 남은 가로 칸 수 + 세로 칸 수. Manhattan 거리다. 실제 남은 거리보다 작을 수 있다.
- A*: `g + h`가 작은 후보부터 검토한다.
- Greedy Best-First: `h`가 작은 후보부터 검토한다.
- Dijkstra: `g`가 작은 후보부터 검토한다.

예를 들어 후보 A의 `g=2, h=2`, 후보 B의 `g=6, h=1`이라면 A*는 총점 4인 A를, Greedy는 남은 추정거리 1인 B를 먼저 검토한다. 실제 로봇이 그 길을 이미 주행했다는 뜻은 아니다.

## 구현과 검증 범위

상하좌우, 이동 비용 1, 정적이고 완전히 알려진 장애물이다. Manhattan 거리는 이 조건에서 실제 최단거리보다 크지 않고 인접 칸에서 일관적이다. 따라서 충분한 예산이 있는 A*는 이 모델에서 최단거리를 찾는다. Greedy에는 최단거리 보장이 없다. 이 설명은 회전 비용·미지 장애물·물리 주행에 그대로 적용되지 않는다.

같은 우선순위는 먼저 넣은 후보부터 처리한다. 이웃 순서는 오른쪽·아래·왼쪽·위다. 빈 지도에서도 이 규칙에 따라 검토한 칸 수가 달라진다. 이 순서 변경은 새로운 알고리즘 발명이 아니며 별도의 실험 변수다.

`expanded`는 중복·낡은 후보를 건너뛴 후 실제 검토한 서로 다른 칸 수다. 출발점과 도착점도 센다. 도착점을 꺼내 확인하기 위한 예산까지 필요하다. 경로 길이는 출발점을 0으로 센 이동 횟수다.

기존 A*와 Dijkstra는 같은 `plan` 함수의 우선순위 계산만 바꾼다. 독립 BFS를 새 테스트에 작성해, 출발·도착점을 고정한 4×3 지도의 장애물 조합 1,024개와 대조한다. 이 유한 검증은 모든 크기·입력에 대한 증명이 아니다. 코드와 개념적 성질을 함께 검토한다.

## 실험 해석의 한계

- 원본 무작위 벤치마크는 Dijkstra로 도달 가능한 지도만 고른다. 실제 환경 전체의 성공률이 아니다. 탈락한 지도 수가 결과에 없다는 제한도 있다.
- 경로 길이 평균은 성공한 실험만 대상으로 한다. 두 알고리즘의 성공 지도가 다르면 단순 평균 비교가 공정한 비교가 아닐 수 있다.
- 고정 seed는 같은 코드에서 재현에 도움을 준다. 독립 표본이나 현실성을 보장하지 않는다.
- 후보 배열을 매번 정렬한다. 확장 노드 수는 실제 실행 시간이나 로봇 에너지 소비량과 같지 않다.
- 반환 경로를 검사하는 `verifyPath`는 BFS와 같은 독립 최단거리 기준이 아니다. 모든 외부 입력 형태를 엄격하게 검증하는 API로도 간주하지 않는다.
- 센서·모터·운동학·실제 충돌·하드웨어 결과는 아직 없다.
