# 예산 100에서 새 탐색과 기존 유효 경로를 구분

2026-10-29. 학생은 작은 예산 50·100 중 **2**, 100을 선택했다. [선택 원문](../data/learning/bound-skip-budget-choice-01.json)은 조건 선택만 기록하고 결과 예측·방법·코드·실행으로 확대하지 않는다. [초안](../experiments/bound-skip-budget-stress.design.json)은 당시 미선택 상태로 보존한다.

## 실행 전 조건

[준비 프로토콜](../experiments/bound-skip-budget100-01.protocol.json)은 이전 벽 생성 확률 .28·기준 시드 20265027의 같은 30개 수정 지도, 현재 시작·목표, 이전 유효 경로, A* FIFO를 그대로 쓰고 **정책 호출별 예산만 300에서 100으로** 줄인다. 벽이나 지도를 다시 고르지 않고 기존 경로를 새로 취득하지 않는다. 생략 없는 재탐색과 하한 생략 적용을 같은 조건에서 새로 실행한다.

같은 입력의 예산 300 결과와 전체 검토량이 이미 알려져 있으므로 새 독립 코호트나 맹검 예측 연구가 아니다. 이번 질문은 작은 예산에서 반환 동작과 비용이 프로토콜대로 유지되는지다.

## 분리할 결과

- **사용 가능한 경로:** 최신 지도에서 검증된 반환 경로가 있는가. 이 실험은 벽 제거 후에도 기존 경로가 유효하므로 새 최적화 실패 시에도 그 경로를 보존한다.
- **하한 증명:** 경로가 현재 위치·목표 사이의 이론적 최소 길이면 새 탐색 없이 최단임을 확인한다.
- **새 탐색 완료:** A*가 새 경로를 끝까지 찾았는가. 기존 경로를 반환하거나 수학적 증명으로 생략한 것을 새 탐색 성공으로 세지 않는다.
- **재최적화 예산 초과:** 원시 `planningResult`의 BUDGET_EXCEEDED·빈 경로·null 길이를 남기고, 상위 반환의 기존 유효 경로와 구분한다. 도착 불가로 바꾸지 않는다.
- **경로 품질:** 반환 길이를 기존 길이 및 이전에 검증한 수정 지도 BFS 거리와 대조한다. 유효한 반환 경로라도 예산 때문에 더 짧은 길을 놓칠 수 있으므로 최단 일치와 가능 개선 누락을 따로 센다.

AI가 [비교 도구](../scripts/compare-manhattan-bound.mjs)의 분석을 보완했다. 원래 전체 탐색이 100칸 이내면 기존 결과 필드를 그대로 대조하고, 더 많은 검토가 필요했던 경우에는 100에서 예산 초과·기존 경로 보존을 검증한다. 탐색 코어와 정책 자체는 바꾸지 않았다.

새 분석 검사 2개를 포함해 [전체 57개 테스트](../data/route-update-policy/bound-budget-stress-tests-01.tap)가 통과했다. 알려진 작은 지도에서 유효하지만 최단이 아닌 예산 실패 경로, 이미 최단인 실패 경로, 탐색 없는 하한 증명과 완료 수 구분, 잘못된 실패/최단 주장 거부를 검사했다. 이는 AI가 작성·실행한 회귀 검사다.

과거 예산 300 결과는 덮어쓰지 않는다. 지도 검사·복사·독립 검증 비용과 탐색기 노드 확장을 구분하며 물리적 주행·실행 시간·에너지를 측정하지 않는다.

## 커밋 후 결과

학생 선택·분석 코드·프로토콜 커밋 `4c78f0aafdfab6babb4bcf5b11fa204b0ef8a022` 뒤 AI가 실행했다. [원시 결과](../data/route-update-policy/bound-skip-budget100-run-01.json)와 [검증](../data/route-update-policy/bound-skip-budget100-validation-01.json)은 같은 수정 지도 30쌍·A* FIFO·호출별 예산 100에서 다음을 보존한다.

| 지표 — 분모 30 | 강제 재탐색 | 하한 생략 적용 |
|---|---:|---:|
| 사용할 수 있는 유효 경로 | 30/30 | 30/30 |
| 하한 증명으로 생략 | 0 | 21 |
| 새 A* 탐색 완료 | 21 | 6 |
| 새 최적화 예산 초과 | 9 | 3 |
| 정책 안에서 최단성 확인 — 증명+완료 | 21 | 27 |
| 별도 검증 BFS 최단 길이와 일치 | 30/30 | 30/30 |
| 평균 반환 이동 횟수 | 26.67 | 26.67 |
| 새 A* 호출 | 30 | 9 |
| 새 검토량 합계 | 2,581 | 798 |
| 지도당 평균 새 검토량 | 86.03 | 26.60 |

하한 생략 방식의 21+6+3=30은 서로 다른 처리 결과다. 새 탐색을 마친 것은 6장이며 21장은 증명으로 생략했고 3장은 예산을 소진했다. 예산 실패 3장도 검증된 기존 경로를 반환했으므로 사용 가능한 길은 남았다. 원시 실패의 빈 경로·null 길이는 별도 `planningResult`에 그대로 남으며 도착 불가로 바꾸지 않았다.

이번 30장에서는 외부 BFS 검증상 반환 길이가 모두 최단과 같았고, 한 장의 28→26 개선도 예산 100 안에서 찾았다. 그러나 예산 실패 3장에 대해 정책의 새 최적화가 완료되거나 최단성을 새로 입증했다고 표현하지 않는다. BFS는 실험 검증용 별도 계산이며 온라인 정책이 무료로 참고한 값이 아니다. 다른 지도에서 유효한 기존 길이 최단이 아닐 가능성은 새 회귀 검사에도 보존한다.

같은 생략 정책의 예산 300 결과(탐색 완료 9·예산 실패 0·검토량 844)와 비교하면, 예산 100에서는 완료 6·실패 3·검토량 798이다. 입력과 정책은 같고 예산만 바뀌었다. 더 적은 검토량이 모든 최적화를 완료했다는 뜻은 아니다. 두 정책 간 검토량 차이는 1,783칸, 약 69.1%이며 이 코호트의 노드 확장량만 비교한 값이다.

이번 재비교 전체는 정책 평가 60건·새 A* 39회·검토량 3,379다. 새 지도 생성·기존 경로 취득·도구 안의 BFS 실행은 없고, 별도 검증 BFS 30회·추가 공유 탐색기 0회를 사용했다. 모든 지도·경로·참조 결과, 예산 경계와 실패 기록, 비용·분모, 57개 테스트·소스 해시와 출력 보존을 확인했다. 설정 실행 뒤 전체 테스트를 반복하지 않았다.

다음 [예산 종료 대응 선택](../experiments/optimization-timeout-response.design.json)은 기존 길이 유효한 상태에서 이번 계산을 끝낼지, 별도 추가 예산을 정해 더 탐색할지다. 당시 유효 경로 보존은 AI가 제안한 기본 처리였다. 학생은 이후 **2**, 추가 탐색을 골랐고 [최신 계속 탐색 정책](ROUTE_CONTINUATION_KR.md)에 반영한다. 초기100→누적150·한 번의 추가 단계는 AI 설정이며 아직 구성된 재비교 전이다. 위 예산100 결과는 당시 retain 모드 기록으로 보존한다.

검증 파일의 별도300예산 비교 요약에는 after 항목명을 중복 사용해 일부 후속 값 이름이 소실된 메타데이터 오류가 있었다. [정오표](../data/route-update-policy/budget100-comparison-erratum-01.json)가 원본 해시와 명시적 전후 항목명으로9→6완료,0→3실패,844→798검토를 연결한다. 원시 결과와 주요 결과 수치는 변하지 않았고 원본 검증 파일도 수정하지 않았다.
