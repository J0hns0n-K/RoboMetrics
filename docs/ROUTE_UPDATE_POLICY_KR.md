# 최신 지도에서 남은 경로를 처리하는 참고 정책

2026-10-29. 앞선 [현재 위치 실험](CURRENT_POSITION_REPLAN_KR.md)은 옛 경로가 막혀도 새 길이 있을 수 있고, 추가 벽에 따라 도착 불가가 될 수도 있음을 확인했다. 학생은 후속 해석에서 통로가 막히면 고립된다고 설명했다. [원문 기록](../data/learning/second-wall-isolation-01.json)은 ‘어디’의 범위를 모든 다섯 위치로 확대하지 않는다. 이 해석은 학생 기여이며 아래 API·규칙·구현·테스트·실행은 AI 지원이다.

[참고 함수](../src/route-update-policy.mjs) `resolveRouteUpdate`는 최신 정적 지도, 이전 경로, 현재 경로 인덱스와 유한 검토 예산을 받는다. 지도 시작점은 실제로 전달받은 현재 위치와 일치해야 한다. 입력 지도는 기존 코어의 조건처럼 시작·목표가 비어 있어야 하며 알려지지 않은 셀이나 센서 오차를 모델링하지 않는다.

| 조건 | 결과 | 새 탐색 |
|---|---|---|
| 현재 위치 이후 남은 경로가 최신 지도에서 유효 | KEEP_ROUTE | 없음 |
| 남은 경로가 무효지만 새 경로를 찾음 | NEW_ROUTE_FOUND | A* 1회 |
| 새 탐색이 연결 영역을 소진하고 경로가 없음 | UNREACHABLE | A* 1회 |
| 새 탐색의 검토 예산이 먼저 소진됨 | BUDGET_EXCEEDED | A* 1회 |

이미 지나온 경로 앞부분은 남은 경로의 장애물 검사에 넣지 않는다. 새 경로는 현재 위치부터 시작하고 성공 시 최신 지도에서 검증한다. 실패의 빈 경로·null 길이와 원래 이유를 유지한다. 반환한 경로를 수정해도 입력이나 별도 원시 탐색 결과의 경로에 영향을 주지 않는다. 결과는 계산상의 분류이며 실제 모터에 이동·정지 명령을 보내지 않는다.

유효한 경로를 그대로 쓰는 것은 **AI가 선택한 참고 기본 규칙**이다. 예를 들어 벽이 없어져 더 짧은 경로가 생겨도 기존 경로가 유효하면 새 탐색을 하지 않는다. KEEP_ROUTE는 최단 보장이 아니라 유효성 확인 결과다. 이 최적화 정책을 학생이 이미 선택한 것으로 기록하지 않는다.

새 검사 6개를 포함해 [전체 43개 테스트](../data/route-update-policy/route-update-policy-tests-01.tap)가 통과했다. 과거 구간의 벽·현재 인덱스 정렬, 새 우회로, 기존 세 벽의 도착 불가, 경로가 있는 지도의 예산 초과, 잘못된 입력, 유효하지만 더 긴 경로와 이미 목표인 경우를 검사했다. AI가 작성·실행한 회귀 확인이며 학생 연구의 추가 독립 표본이 아니다.

[설정](../experiments/route-update-policy-controls.config.json)은 기존 원시 지도를 재사용한 알려진 통합 조건 7개를 명시한다. 정책이 호출하는 새 탐색은 다시 실행된 것으로 비용을 기록하며, 원시 파일을 단순 참조한 것과 혼동하지 않는다. 소스·설정 커밋 후 실행 결과를 새 이름으로 보존할 예정이다.

현재 범위는 명시적으로 전달된 최신 지도에서의 경로 검사와 새 정적 탐색이다. 자동 지도 갱신·센서 감지·기존 탐색 상태의 점진적 복구·물리적 주행·실행 시간 또는 에너지 개선은 구현·검증하지 않았다. 웹 데모에도 아직 연결하지 않았다.
