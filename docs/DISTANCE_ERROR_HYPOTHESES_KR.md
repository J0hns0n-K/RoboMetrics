# 한 거리의 오차만으로 보정 방식을 정할 수 있는가?

이 자료의 숫자는 **AI가 만든 설명용 가상값**이다. 로봇을 움직이거나 실제 거리·정확도를 측정한 결과가 아니다. [대화 기록](../data/learning/calibration-distance-range-choice-01.json)은 다음 안내된 답을 보존한다. 학생은 평균30cm만으로 매번30cm라고 할 수 없다고 답했고, 같은29cm를 세 번 가는 가상 B를 더 일정한 쪽으로 골랐다. 이어30cm명령만 반복하는 대신60cm명령도 비교하는2번 방법을 선택했다. 이유·새 코드·실제 시행을 제공한 것은 아니다.

## 두 가정이 같은 예시를 설명한다

가상 예시의 기준은30cm명령에29cm응답이다. 이 점만 보면 아래 두 가정은 구분되지 않는다.

| 설명용 가정 | 수치식 | 30cm에서의 예측 | 60cm에서의 조건부 예측 |
|---|---|---:|---:|
| 항상1cm덜 간다 | 명령값 −1 | 29cm | 59cm |
| 명령 거리의29/30만큼 간다 | 명령값 ×29/30 | 29cm | 58cm |

모든 예측값과 식은 AI가 제공한 가정에 따른 조건부 산술이다.60cm열은 이후 학생의 매개변수 수정 뒤 AI가 실행한 프로그램 출력과도 일치했다. 실제 측정이나 학생이 제시한 수치 예상은 아니다. 실제 로봇에서는 다른 오차 모형도 가능하고, 반복 편차·측정 오차까지 함께 봐야 한다. 두 거리만 시험했다고 전 구간에 맞는 보정식을 증명하거나, 두 가정 중 하나가 반드시 참이라고 할 수는 없다.

## 컴퓨터 실습

[21-distance-error-hypotheses.mjs](../practice/21-distance-error-hypotheses.mjs)는 로봇 연결 기능이 없는 AI 참고 코드다. 기준 가상 예시를 두 가정에 넣어 예측만 출력한다. 출처와 데이터 종류는 코드·출력·[확인 기록](../data/learning/distance-error-hypotheses-demo-check-01.json)에 명시했다. 소스 `5a01d4fbb8df91c01d61578c23c380792e343686`에서 AI가 기본 시험 거리30으로 한 번 실행했고, 두 가정 모두29를 출력했다.140개 과거 파일과 원래30cm계획·빈 양식을 보존했다. 기존166통과 소스/TAP가 같아 전체 회귀 검사는 반복하지 않았다. 이 기록은 기본30실행만 포함하며, 이후60실행은 별도 원본으로 보존한다.

학생에게 안내한 작업은 아래 한 줄의30을60으로 바꾸는 것이었다.

```js
const probeCommandCm = 30;
```

학생은 **저장함**이라고 보고했고, [실제 파일의 단일 매개변수 수정](../data/learning/distance-error-student-edit-01.json)을 확인했다. 두 기준값과 식은 그대로였다. 저장 보고와 일치하는 숫자 수정만 학생에게 귀속하고, 편집기 조작 과정이나 학생의 직접 실행을 관찰한 것으로 기록하지 않는다. 원래 참고 코드·가상값·수식·실행은 AI 지원이다.

## 실제 실험으로 연결할 조건

[추가 거리 비교 설계](../experiments/calibration-distance-range-01.design.json)는 향후30cm와60cm에서 오차의 거리 의존성을 조사하는 방향이다. 기존 [30cm프로토콜 초안](../experiments/straight-distance-30cm-01.protocol-draft.json)과 [빈10행 양식](../experiments/templates/straight-distance-30cm-01.session-template.json)은 그대로 보존한다.60cm시도의 반복 횟수·순서·하드웨어 프로그램은 아직 정하지 않았으므로 새로운 완성 프로토콜이나20회 시행으로 기록하지 않는다.

실제로 비교하기 전에는 같은 로봇·프로그램/제어 설정·속도·바닥·출발 방향·거리 기준점을 고정하고, 순서·배터리 상태의 영향과 측정 불확실성을 고려해야 한다. 지금은 추가 거리 방법을 고른 계획/학습 단계다. 로봇 구매·도착·바닥 표시·실제 측정·보정 계수·보정 효과를 확인한 상태가 아니다.


## 학생이 바꾼60cm입력의 확인 결과

학생의 한 줄 수정을 [별도 커밋](https://github.com/J0hns0n-K/RoboMetrics/commit/d2e582690d05e286ac22cc1207a3c3b4b33b0470)에 고정한 뒤 AI가 실행했다. [사전 확인 프로토콜](../experiments/distance-error-hypotheses-60-01.protocol.json), [새 출력·검증 원본](../data/learning/distance-error-hypotheses-demo-check-02.json)은 소스 `d2e582690d05e286ac22cc1207a3c3b4b33b0470`에 묶인다. ‘항상1cm덜 감’은59cm, ‘명령 거리의29/30’은58cm를 출력했다. 기준30→29와 두 식은 바뀌지 않았으며, 기본30실행은 다시 하지 않고 기존 원본에서 비교했다.

독립 Python 산술과 출력의 가상값 표기가 일치했다. 새 확인은 AI의 CLI1회·60cm조건부 예측2개이며, 실제 주행·물리 측정·탐색·경로 시간 평가와 전체 회귀 검사 실행은 없다.141개 보존 원본/입력 파일과3개 이번 소스/프로토콜/수정 기록의 해시를 확인했다. 원래30cm물리 프로토콜·빈 양식·과거 출력·기존166통과 소스/TAP는 보존한다.

한 가상 기준점에서 같던 두 예측이 다른 입력에서 갈라진다는 소프트웨어 설명용 결과다. 실제 로봇의 정답, 보정 효과나 두 모형 중 하나의 타당성을 확인한 것은 아니다. 다음은 [이 출력만으로 실제 오차 모형을 선택할 수 있는지 설명](../experiments/distance-error-hypotheses-interpretation-01.design.json)하는 단계다.
