# 유효 경로를 보존하며 예산을 한 번 늘려 계속 최적화

2026-10-29. 예산100에서 최적화를 못 끝냈지만 기존 길이 유효한 상황에 학생은 **2, 추가 예산으로 계속 탐색**을 선택했다. [선택 원문](../data/learning/optimization-timeout-choice-01.json)은 대응 선택만 기록한다. AI가 초기100·추가50·누적 목표150·추가 단계1회·상태 재사용을 구현한 것이다. 수치나 새 알고리즘·코드를 학생 저작으로 확대하지 않는다.

## 현재 기본 동작

[정책](../src/route-update-policy.mjs)은 먼저 최신 지도에서 남은 길을 검사하고, 하한 달성 시 기존처럼 생략한다. 탐색이 필요하고 기존 유효 경로가 있으면 A* 상태를 저장해 시작한다. 첫 한도를 소진한 경우에만 같은 지도 복사본에서 누적 한도를 한 번 늘려 이어간다. 성공·도착 완료·하한 증명에는 추가 예산을 쓰지 않는다. 두 번째에도 예산 초과이면 유효한 길과 모든 실패 기록을 보존하고 멈춘다. 기존 길이 무효인 실패에는 이번 ‘유효 경로가 있는 경우’의 계속 규칙을 적용하지 않는다.

기본 옵션은 `timeoutResponse: 'continue'`, `additionalExpansions: 50`, `continuationStrategy: 'resume'`다. `retain`으로 이전 종료 동작을, `restart`로 새 탐색 대조를 지정할 수 있다. 과거 실험 도구는 retain을 명시해 원래 프로토콜을 유지한다. 지도·현재 위치는 단계 사이 바뀌지 않는 고정 스냅샷이며, 자동 센서 갱신·주행 명령·비동기 운동 중 재계획 기능이 아니다.

## 비용과 한도의 뜻

- 재사용은 첫100 이후 **새로 최대50**을 확장해 누적150까지다. 단계 결과의 누적expanded를 단순히 더하지 않고 `expandedThisStage`를 합친다.
- 재시작 대조는 첫100을 버린 뒤 새 검색 한도150으로 시작한다. 최악의 실제 일은100+150=250이며 이를 ‘추가50만 사용’이라고 쓰지 않는다.
- 비교는 같은 최종 탐색 한도150이며 각 방식의 실제 최대 비용을100·150·250으로 밝힌다. 공통 비교 한도는250이지만 선택된 재사용 방식은150 이내다. 전역 무한 예산이나 반복 재시도를 허용하지 않는다.
- `plannerCalls`는 새 A* **검색 세션 수**다. 기존 일회성 엔진 호출은 `corePlanCalls`, 이어가기의 한도 갱신 호출은 `resumeAdvanceCalls`, 단계는 `searchStages`로 따로 기록한다. 하나의 세션에 두 단계가 있어도 새 검색 세션2개로 세지 않는다.

각 단계의 원시 성공/실패·경로·한도·단계별 새 확장량을 유지한다. 최종 `planningResult.expanded`는 마지막 세션의 누적량이며 최상위expanded는 모든 세션의 실제 작업 합계다. 재시작에서는 둘이 달라질 수 있다. 이 비용은 지도 복사·경로 검사·큐/메모리 오버헤드나 실행 시간·에너지 측정이 아니다.

## 확인과 준비된 재비교

새 검사6개를 포함해 [전체63개 테스트](../data/route-update-policy/continuation-tests-01.tap)가 통과했다. 첫 실패 보존·재사용/재시작 비용·초기 성공과 증명 시 종료·한 번 더 실패하면 중지·무효 경로의 적용 범위·현재 인덱스와 두 동점 규칙·독립 반환 경로를 검사했다. 테스트·구현·실행은 AI 지원이다.

[준비 프로토콜](../experiments/route-continuation-100-150-01.protocol.json)은 같은 알려진30장·A* FIFO에서100종료/100→150재사용/100→150재시작을 각각 실행한다. 예산100첫 단계와 기존 원시 결과를 대조하고, 최종 결과와300한도 참조도 비교한다. 새 코호트·독립 재현·맹검 예측 연구가 아닌 유한 예산 통합·비용 확인이다. 소스·프로토콜 커밋 후 실행하며 아직 구성된 결과는 없다.
