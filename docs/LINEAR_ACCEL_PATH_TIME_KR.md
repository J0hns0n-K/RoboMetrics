# 정지 규칙과 직진 가속·감속 시간

학생은 제시된 두 규칙 중 **2/ 더 빠르잖아**라고 답해 직선의 중간점은 이어 가고 방향 변경 때 정지하는 모델을 골랐다. [원문](../data/learning/stop-turn-policy-choice-01.json)은 설계 선택과 질적인 속도 기대다. 수치 예측·모든 경로에 대한 증명·실제 로봇 성능 주장으로 확대하지 않는다. 속도·가속도 한계·수식·코드·검사·실행·검증은 AI 지원이다.

## 새 참고 모델의 경계

[linearAccelStopTurnTime](../src/linear-accel-path-time.mjs)은 출발·도착과 필요한 중간 정지 지점에서 직진 속도가0이라고 두고, 직진 구간의 대칭 가속·순항·감속 시간을 구성한다. 새 API의 기본값만 학생이 고른 `turns-only`이며 `every-waypoint`를 비교용으로 명시적으로 남겼다. 기존 명목 시간·가상 점수·A*·Greedy·브라우저 기본값은 바꾸지 않았다.

- `turns-only`: 같은 방향의 연속 구간을 합친다. 방향 변경 전과 도착에서 정지한다.
- `every-waypoint`: 제공된 중간 경유점마다 정지한다. 경유점 수를 바꾸면 요구되는 정지 작업도 바뀐다.

구간 거리D, 최대 속도v, 가속·감속 크기a에서 전이 거리는 `v²/a`다. 짧은 구간은 최고 속도에 못 미치는 삼각 속도 프로필로 `2√(D/a)`초, 긴 구간은 순항을 포함해 `D/v + v/a`초다. 각 구간은 [기존 선형 속도 참고 함수](LINEAR_SPEED_RAMP_KR.md)의 가속·감속 상태로 구성하고, 거리·휴지 끝점·속도/가속도 한계를 확인한다.0거리 구간의 시간은0이며 빈 실패 경로는 거부한다.

이번 변경은 **직진의 가속·감속만** 유한하게 만든다. 회전은 여전히 최소 각도를 일정 각속도로 나누며 각속도는 즉시 바뀐다고 가정한다. 전진과 제자리 회전은 순차적이고, 가속도 자체의 순간 변화·휠 운동학·곡선 주행·미끄러짐·추종 제어·센서·충돌·하드웨어 보정은 모델링하지 않았다. 시작 방향은 명시하고 도착 후 별도 방향 정렬은 요구하지 않는다.

## 같은 경로의 두 정지 규칙 비교

[입력](../experiments/linear-accel-path-01.config.json), [실행 전 프로토콜](../experiments/linear-accel-path-01.protocol.json), [결과·검증](../data/learning/linear-accel-path-run-01.json), [전체 검사 TAP](../data/learning/linear-accel-path-tests-01.tap)는 소스 `bcb4eaeddff127185abc9cdceb21218460b89aca`에 연결된다. 같은 설명용 X/Y 좌표, 출발 방향down, 직진 최고 속도1가상칸/초, 가속·감속 크기1가상칸/초², 각속도180도/초를 사용한다. 값은 실측이 아닌 모델 초다.

| 경로 | 매 중간점 정지 | 방향 변경 때 정지 | 후자의 감소량 |
|---|---:|---:|---:|
| X | 15초 | 15초 | 0초 |
| Y | 17초 | 12초 | 5초 |

X는 모든 중간점에서 방향을 바꿔 두 규칙 모두5번의 중간 정지가 필요하다. Y는 중간 정지7번을2번으로 줄여 직진 시간이16→11초가 됐다. 회전 시간은 각 경로에서 그대로X3초/Y1초다. 따라서 선택한 규칙의 이득은 이번 조건에서 경로 모양에 따라 다르다. AI가 추가한 직선3칸 예제도 같은 선형 한계·출발right에서 매점 정지6초 대 이어 가기4초다.

기존 즉시 일정 속도 모델의 X9초/Y9초는 [별도 원본](../data/learning/path-nominal-time-run-02.json)으로 바이트까지 보존했다. 물리 가정이 다른 두 모델을 같은 실측 결과인 것처럼 섞지 않는다. 두 제공 경로 사이의 비교이지 전체 최속 경로를 구한 것이 아니다.

## 경유점 간격에 대한 확인

같은 직선 길이3을1칸·반 칸 간격으로 나누어도 `turns-only`는 한 번의 직진 구간으로 처리해 둘 다4초다. `every-waypoint`는 요구된 정지가 달라져1칸 간격6초·반 칸 간격 약8.49초다. 후자는 서로 다른 정지 작업이며 동일한 물리 작업의 공정한 해상도 비교라고 부르지 않는다. 새 기본값의 공선 분할 불변성은 검사와 별도 구성 사례로 확인했다.

추적된 `test/*.test.mjs`28개 파일의 검사141개가 모두 통과했다. 이 중 새 모델 검사12개가 포함된다. 기존 플래너·생성기 회귀 검사도 이 실행에 포함되며 새로운 연구 표본으로 세지 않는다. AI는 실습09를 한 번 실행해 X/Y4개·직선4개, 총8개의 해석적 모델 평가를 보존했다. Python이 경로 구간과 시간식을 따로 재구성하고 직진 프로필34개·속도 위상72개의 연속성·휴지 끝점·한계·거리·시간을 확인했다. 각 위상은64구간 속도 적분으로도 확인했다. 구성된 모델 평가는 플래너/BFS를 호출하지 않고 독립 지도도 추가하지 않았다.

학생은 결과를 본 뒤 **계속 방향을 바꿨으니까 그렇지. 직선에서는 속도가 빨라지는데 방향을 계속 바꾸니까 그렇지.**라고 [설명](../data/learning/linear-accel-path-interpretation-01.json)했다. 이는 이 모델에서 방향 변경 전 정지가 필요하다는 조건에 맞는 질적 해석이다. 직선에서도 속도는 정해진 최고 속도까지만 증가하며, 학생에게 수치 계산이나 새로운 실행을 귀속하지 않는다. 학생은 이어 `→ ↓ ↓ → ↓ →`를 [직접 설계](../data/learning/linear-accel-route-design-01.json)했다. [새 비교 결과](../data/learning/linear-accel-route-run-01.json)는 [프로토콜](../experiments/linear-accel-route-01.protocol.json)·[입력](../experiments/linear-accel-route-01.config.json)과 소스 `108261e3c363ca2af1cfd7f172d4fc8fd1de14c5`에 연결된다. 같은 출발·도착·거리6·출발down·2번 규칙·직진속도1/가속도1/각속도180에서 중간 정지는5→4번, 직진 시간은12→11초, 회전은3→2.5초로 총15→13.5모델 초다. AI가 기존 모델 검사12개와 별도 좌표·구간·시간식·위상 한계 확인을 수행했다. 이전 전체141개 검사는 반복하지 않았고, 새 지도나 플래너 실행도 없다. 학생은 화살표 순서를 설계했으며 좌표 변환·코드·실행·검증은 AI 지원이다. 다음은 [방향을 정확히1번 바꾸는 같은 길이의 순서 설계](../experiments/linear-accel-route-design-02.design.json)이며 새 답은 아직 없다. 실제 이동 시간·회전 가속도·동역학·제어·충돌 검증과 보정된 실험은 여전히 별도 후속 작업이다.
