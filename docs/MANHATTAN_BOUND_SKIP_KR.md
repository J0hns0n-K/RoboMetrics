# 최소 길이를 증명할 수 있을 때 재탐색 생략

2026-10-29. 앞선 [30장 비교](ROUTE_REOPTIMIZATION_BATCH_01_KR.md)는 선택한 벽을 없애도 길이가 줄지 않았고, 28장은 이미 맨해튼 하한 26번이었다. AI가 최신 지도에서 유효한 경로가 하한을 달성하면 재탐색을 생략하자고 제안했고 학생은 **1**을 선택했다. [선택 원문](../data/learning/manhattan-bound-choice-01.json)은 제안 채택과 AI의 증명·코드·테스트·실행을 구분한다. 이전 초안·결과는 그대로 보존한다.

## 규칙과 정확성 범위

현재 위치에서 목표까지 가로 차이와 세로 차이의 합보다 적은 네 방향 이동으로는 목표에 도달할 수 없다. **최신 지도에서 남은 경로가 유효하고** 그 이동 횟수가 이 하한과 같으면 최단임이 증명된다. 먼저 경로를 검사하고, 막힌 옛 길은 하한과 길이가 같아도 생략하지 않는다. 이미 지난 구간이나 원래 출발점 대신 현재 인덱스부터의 남은 구간을 사용한다.

[정책 API](../src/route-update-policy.mjs)의 기본값은 재최적화와 `skipProvenOptimal: true`다. 하한 달성 시 `decisionReason: LOWER_BOUND_OPTIMAL`, `optimalityEvidence: MANHATTAN_BOUND`, 새 탐색 호출·검토량 0을 반환한다. 이는 A*를 실행해 완료했다는 뜻이 아니다. 하한보다 긴 유효 경로는 기존처럼 예산 안에서 재탐색한다. 실패 시 유효 경로 보존과 예산 초과의 구분도 유지한다. `skipProvenOptimal: false`로 이전의 강제 재탐색과 비교할 수 있다.

적용 범위는 알려진 정적 격자·네 방향·단위 비용이다. 대각선 이동·다른 비용·센서 오차·주행 동역학에 대한 규칙으로 확대하지 않는다. 지도 복사·경로 검사 비용은 필요하며 새 확장 0을 전체 계산 0이나 시간·에너지 개선으로 표현하지 않는다. 웹·물리적 로봇에 연결하지 않았다.

## 사전 확인과 재비교 방법

[전체 55개 테스트](../data/route-update-policy/manhattan-bound-tests-01.tap)가 통과했다. 새 검사 5개는 기본 생략/해제, 막힌 옛 최소 경로의 재탐색, 현재 위치·과거 구간 구분, 하한보다 긴 최단 우회로, 4×3의 1,024가지 장애물 배치와 두 동점 규칙의 2,048개 쌍 대조를 포함한다. 이는 AI 회귀 검사이며 독립 연구 표본이 아니다.

[준비 프로토콜](../experiments/manhattan-bound-comparison-01.protocol.json)은 이전 30장의 수정 지도·시작·목표·기존 경로·순서를 그대로 사용한다. 새 표집·벽 선택·기존 경로 취득을 하지 않는다. A* FIFO·예산 300을 고정하고, 현재 소스에서 강제 재탐색·새 기본값을 각각 실행한다. 강제 재탐색의 원래 결과 필드·경로·검토량을 옛 원시 결과와 대조한다. 두 방식의 새 실행 비용은 모두 기록하고, 수학적 증명으로 생략한 수와 실제 A* 완료 수를 분리한다.

이는 규칙을 제안할 때 본 **같은 개발 코호트에서의 재비교**이며 새 검증 코호트가 아니다. 소스·프로토콜 커밋 뒤 실행하고 새 원시 이름으로 보존한다. 아직 설정된 재비교 결과는 없다. 정확한 절약량을 학생이 예상하거나 독립적으로 구현했다고 기록하지 않는다.
